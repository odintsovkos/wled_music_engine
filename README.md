# WLED Music Engine

Android-приложение, которое анализирует звук, воспроизводимый на телефоне, и синхронизирует с музыкой лампы на прошивке [WLED](https://kno.wled.ge/) по локальной сети — без микрофонов на контроллерах, без интернета и внешних серверов.

> Статус: **Этап II — RGB Engine (реализован, идут полевые тесты).** Два режима управления лампой:
> **Audio Reactive** (Этап I: признаки звука по Audio Sync v2, эффекты считает прошивка) и
> **RGB Engine** (телефон сам рисует 6 эффектов для ленты или матрицы и шлёт пиксели по DDP).
> После сессии лампа возвращается в прежнее состояние.

## Как это работает

```
Системный звук Android ──► DSP на телефоне ─┬─► UDP 11988 (Audio Sync v2) ──► WLED, usermod Audio Reactive   [Audio Reactive]
 (AudioPlaybackCapture)     FFT, уровни,     └─► рендер эффекта ──► UDP 4048 (DDP) ──► WLED realtime           [RGB Engine]
                            акценты
```

Эффекты RGB Engine: Spectrum, VU Pulse, Beat Flash, Ripple, Flow, Ambient Glow — у каждого есть
вариант для ленты и для матрицы. Раскладка (лента N LED или матрица W×H) определяется по
`/json/info`; поворот, отражения, змейку и направление анимации можно поправить вручную.
Частота вспышек ограничена тремя в секунду.

Перед сессией приложение снимает `/json/state` и записывает в журнал всё, что меняет на лампе
(в Этапе II — только live override, с согласия пользователя). После остановки — `{"live": false}`
и откат журнала; поле, изменённое за время сессии самим пользователем, не трогается.

- Звук захватывается через официальный API `AudioPlaybackCapture` + `MediaProjection` с согласия пользователя.
- Аудио **не записывается** и **не отправляется** в сеть: наружу уходят только агрегированные признаки (уровень, 16 частотных полос, пик) или цвета светодиодов — на адрес, указанный пользователем.
- Нет аналитики, рекламы и облачной авторизации.

## Требования

- Телефон на Android 16 (API 36).
- Контроллер WLED:
  - для **Audio Reactive** — usermod Audio Reactive, Sound → Sync → **Receive**, порт `11988`;
  - для **RGB Engine** — Sync → Realtime → **Receive UDP realtime** (включено по умолчанию), до 1024 LED; usermod не нужен.
- Телефон и контроллер в одной Wi-Fi-сети (или телефон подключён к точке доступа WLED).

## Сборка

Нужны JDK 17+ и Android SDK (platform 36).

```bash
./gradlew test assembleDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk`. Сборка также выполняется в GitHub Actions на каждый push/PR.

## Структура

| Модуль | Назначение |
|---|---|
| `app` | UI (Jetpack Compose: Sync · Devices · Effects · Settings, Pro Audio), Foreground Service синхронизации |
| `core/audio` | Захват системного звука (MediaProjection, AudioRecord) |
| `core/dsp` | DSP-движок на чистом Kotlin: FFT, полосы, нормализация, onset |
| `core/network` | WLED JSON API, Audio Sync v2, DDP, восстановление состояния лампы, замер задержки |
| `core/render` | RGB Engine на чистом Kotlin: раскладки, палитры, 6 эффектов, рендер-цикл |

## Ограничения захвата звука

- Android позволяет захватывать звук только приложений, которые это разрешают. Некоторые проигрыватели и стриминговые сервисы запрещают захват — в этом случае приложение покажет подсказку, звук будет «тишиной». Обход DRM и системных политик не выполняется и не планируется.
- Каждый запуск синхронизации требует системного подтверждения захвата — так устроен Android, автоматического перезапуска нет.
- На Android 16 (проверено на vivo V2324A) захват продолжается при заблокированном экране. Если система всё же остановит захват (отзыв разрешения, «Остановить» в плашке демонстрации экрана), приложение покажет «Остановлен системой» и не перезапустится само. Подробности — `docs/field-test-stage1.md`.
