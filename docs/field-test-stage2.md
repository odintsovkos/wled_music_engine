# Полевой тест — Этап II (RGB Engine)

Протокол ручной проверки режима RGB Engine, восстановления лампы и нового UI.
Каждая строка таблицы результатов — отдельный прогон; неудачные прогоны не удаляются.

## Стенд

| Компонент | Значение |
|---|---|
| Телефон | vivo V2324A (PD2324), Android 16 (API 36) |
| Сборка | debug из GitHub Actions (артефакт `app-debug`) |
| Эмулятор WLED | `tools/fake_wled.py --matrix 16x16` на ПК (UDP 11988 + DDP 4048 + HTTP 80) |
| Реальная лампа | WLED 16.0.0, ESP32, матрица 16×16 (256 LED), 192.168.0.124 (другая подсеть) |

```bash
python tools/fake_wled.py --matrix 16x16     # или --leds 60 для ленты
```

Эмулятор раз в 2 с пишет число DDP-кадров, кадры/с, неполные кадры, среднюю яркость и `live`.
`POST /json/state` с `{"live": false}` сбрасывает realtime сразу.

## Разведка протокола (задачи 1.2–1.5, 2.5) — до оценки эффектов

| # | Проверка | Как | Ожидание |
|---|---|---|---|
| P1 | `/json/info`, `/json/state` лампы | `curl http://192.168.0.124/json/info` и `/json/state` → сохранить в `core/network/src/test/resources` | Есть `leds.matrix {w:16,h:16}`, `mainseg`, `lor` |
| P2 | DDP из другой подсети | Кнопка «Проверить раскладку» на экране ориентации | `info.live = true`, `lm = "DDP"`, `lip` = IP телефона |
| P3 | `{"live": false}` | Остановить сессию RGB Engine | Лампа за ≤ 2 с возвращается к своему эффекту |
| P4 | 2D-карта WLED и DDP | Тестовый узор: красная первая строка вверху, белая диагональ из левого верхнего угла | Узор ориентирован правильно без ручной коррекции |
| P5 | Выключенная лампа | `on = false`, старт RGB Engine | Зафиксировать: показывает ли WLED realtime на выключенной лампе |
| P6 | «Use main segment only» | Включить в WLED, старт на ленте | Кадр ложится в основной сегмент |
