# Полевой тест — Этап I (технический прототип)

Протокол ручной проверки сквозного конвейера «системный звук → DSP → UDP Audio Sync v2 → WLED».
Каждая строка таблицы результатов — отдельный прогон; неудачные прогоны не удаляются.

## Стенд

| Компонент | Значение |
|---|---|
| Телефон | vivo V2324A (PD2324), Android 16 (API 36) |
| Сборка | `0.1.0-prototype`, debug |
| Сеть | Wi-Fi 5 ГГц, 802.11ax; телефон 192.168.1.200 |
| Эмулятор WLED | `tools/fake_wled.py` на ПК 192.168.1.173 (UDP 11988 + `/json/info`) |
| Реальная лампа | WLED 16.0.0, ESP32, матрица 16×16 (256 LED), 192.168.0.124 (другая подсеть) |
| Источник звука | YouTube (фоновое воспроизведение) |

`tools/fake_wled.py` принимает пакеты по тем же правилам, что прошивка (ровно 44 байта, заголовок `00002`),
и раз в 2 с пишет число пакетов, частоту, число битых пакетов, акценты и спектр.

```bash
python tools/fake_wled.py
```

## Наблюдения для следующих этапов

- Реальная лампа в подсети 192.168.0.x, телефон — в 192.168.1.x: unicast через маршрутизатор возможен, multicast 239.0.0.1 туда не дойдёт. Для LAN-сценария предпочтителен unicast.
- Реальная частота пакетов ограничена частотой DSP-кадров (hop 1024 при 48 кГц ≈ 46,9/с), а не только лимитом отправителя.
- Акцентов ~3 в секунду на плотной электронике — возможно, стоит поднять порог onset на Этапе II.

## Итог Этапа I и известные пробелы

Этап I закрыт 2026-09-30 по решению пользователя. Сборка и unit-тесты в GitHub Actions проходят, debug APK публикуется артефактом `app-debug`. Сквозной конвейер работает с реальной лампой WLED 16.0.0;
главный риск (остановка захвата при блокировке экрана на Android 16) не подтвердился.

Не проверено на устройстве — перенести в полевые тесты следующих этапов:

- Задержка «звук → свет» ≤ 100 мс (съёмка 240 fps) и визуальная оценка после перехода на AGC к среднему.
- Переключение между приложениями во время сессии; проводные наушники.
- Плеер, запрещающий захват (подсказка), и выбор «одно приложение» в диалоге записи экрана.
- Direct AP (телефон подключён к точке доступа WLED) и непрерывный прогон 60 минут.
- Отказ в runtime-разрешении / отмена диалога записи экрана и 10 циклов старт/стоп (пропущено, покрыто unit-тестами).
- Время DSP в release-сборке: в debug на телефоне 1,2–1,7 мс/кадр при бюджете 2 мс.
